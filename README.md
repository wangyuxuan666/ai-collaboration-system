# AI 协作体系

核心目的：以节省资源的方式去做出精准的项目。

这是一套让 AI 按规则协作的工作体系。你只需要把任务告诉 AI，AI 会根据任务选择需要的角色、流程、知识和工具，带着你完成工作。

## 第一次使用

1. 下载或克隆本仓库。
2. 把仓库目录交给 AI。
3. 告诉 AI：

   > 请先读取仓库根目录 README 和协作入口，再开始工作。

4. 直接告诉 AI 你要做的事情。

缺少 MCP、Skill、程序依赖或运行环境时，AI 会先说明缺少什么，再按照安装指引带你安装和验证。

## 日常使用

你不需要先研究所有目录，直接描述任务即可。例如：

> 帮我开发一个登录功能，先理解项目，再按协作体系开始执行。

> 帮我整理这次项目中可以长期复用的经验。

> 帮我把这份资料整理成知识库内容。

AI 会从[协作入口](./协作入口/README.md)开始，按当前任务读取必要内容。

## 体系包含什么

- `协作入口`：AI 启动时读取的规则和任务路由。
- `角色`：产品、开发、测试、设计、项目治理等专业角色和流程。
- `代码开发`：软件开发流程、框架参考和项目协作规范。
- `知识库`：知识查询、资料收集、审核和沉淀。
- `自成长`：当前用户的画像、经验和长期协作记忆。
- `工具`：MCP、Skill、安装指引，以及改造后的 `agentbrain`。
- `可视化工作台`：查看体系结构和主要协作流程。

## 个人数据和公开仓库

本仓库适合公开发布，提供的是规则、模板、流程、改造后的源码和安装指引。

用户下载后，自己的画像、经验、记忆、收集资料和工作台运行数据会保存在本机，不与仓库中的其他用户共享，也不会作为仓库内容上传。

可视化工作台首次运行更新脚本时，会自动生成本机需要的公开模板和运行数据。以后如果本机已有自己的静态配置，脚本会保留它，不会覆盖。

具体的公开边界见[仓库运行边界](./仓库运行边界.md)。

## 工具安装

使用某项功能时，AI 会检查对应工具是否可用。需要查看或补齐工具时，进入：

- [MCP 登记](./工具/MCP/README.md)
- [MCP 安装指引](./工具/MCP/安装指引.md)
- [Skill 登记](./工具/skills/README.md)
- [Skill 安装指引](./工具/skills/安装指引.md)

其中 `agentbrain` 是本体系改造过的 MCP，源码随仓库保留；其他第三方 MCP 和 Skill 按安装指引从原始来源获取。

## 可视化工作台

首次使用或需要刷新体系结构时，运行：

`人工维护/可视化工作台更新数据.bat`

脚本会扫描当前仓库结构，并在本机生成工作台数据。工作台数据和个人静态配置属于运行文件，不需要提交到 GitHub。

## 借鉴和第三方内容

本仓库同时包含自建内容、改造内容和借鉴的第三方内容。第三方框架、源码、工具和资料不代表本体系原创，使用时应遵守各自的许可证和来源要求。

具体来源、许可证和改造说明见[第三方内容说明](./THIRD_PARTY.md)。

## 出现问题时

- 缺少工具或依赖：让 AI 按安装指引补齐并验证。
- 工作台没有数据：运行可视化工作台更新脚本。
- 没有个人画像或经验：这是新用户的空白状态，不代表系统损坏。
- 需要了解某个模块：先打开该模块的入口文件，按入口继续读取。
