# 小程序 — 框架说明书（技术经理选型用）

## 是什么

微信/抖音**原生小程序**前端骨架（各一套），**后端默认用纯净骨架后端**（Web 与小程序共用，不另建后端）。骨架自带请求封装、登录流程、目录约定，拿到就能写业务。

## 技术栈

- 前端：微信小程序原生（基于 [Weapp-Starter](https://github.com/MatrixCross/Weapp-Starter) 规范模板，TS + Vant/TDesign + MobX + UnoCSS）、抖音小程序原生（**TS**，官方 TS 方案，TTML/TTSS）——各自独立工程
- 后端：**纯净骨架后端**（Spring Boot 3.5 + MyBatis-Plus + JWT），两套小程序共用一个后端
- 登录：小程序授权登录（wx.login / tt.login 拿 code → 后端换 token），骨架为模拟登录，接真实平台时替换

## 有什么

- 前端微信：规范化模板（TS 工程化、MobX 状态、Vant/TDesign 组件库、UnoCSS、分包结构）+ 已适配纯净骨架后端（请求封装对齐 `{code,data,message}`、自动带 token、401 跳登录）+ 登录页示例
- 前端抖音：目录约定（api/utils/pages）、请求封装（自动带 token、统一错误处理、401 跳登录）、登录页 + 首页示例、**TypeScript 类型声明**（官方 @douyin-microapp/typings）、项目配置
- 后端：`POST /api/v1/auth/miniapp-login` 小程序登录接口（入参 `{code, platform}`，platform 为 wechat/douyin）+ 纯净骨架全部能力（分层、统一响应、异常处理、JWT）

## 能达到什么效果

- 小程序项目免去从零搭工程：登录链路、请求封装、目录结构开箱即用，直接写业务
- 后端只维护一份（纯净骨架），微信/抖音共用，改一次两边生效
- 前后端契约已对齐（`{code,data,message}`、Bearer token、401 处理）

## 适合

- 需要微信小程序 / 抖音小程序的项目（可只要一个平台，也可两平台共用后端）
- 小程序 + Web 都有的项目（Web 用纯净骨架前端，小程序用本骨架，共用纯净骨架后端）

## 不适合

- 需要小程序后台管理页面（登录/角色/菜单）的项目——小程序端通常不适用后台管理形态
- 跨端需求复杂（多端复用一套代码）——本骨架是原生两套，若要多端一套考虑 uni-app/Taro（另议）

## 选型建议

项目是**微信/抖音小程序** → 推荐本方案。给客户的话术："推荐选**小程序**框架（微信/抖音按需），后端默认用**纯净骨架后端**，理由是两套小程序共用一个后端，前后端契约已对齐，开发成本最低。"

## 落地方式

1. 按需复制 `微信小程序\frontend\` 或 `抖音小程序\frontend\` 到新项目
2. 后端：直接用[纯净骨架后端](../纯净骨架/后端/开发说明书.md)（启动方式见其说明书；小程序登录用 `miniapp-login` 接口）
3. 改 `utils/config.js` 的后端地址（开发本地 / 生产 https 域名）
4. 在微信/抖音开发者工具导入工程（替换 appid），写业务
