# 后端开发说明书（纯净骨架）

> 自搭骨架：Spring Boot 3.5 + JDK21 + MyBatis-Plus + JWT。**Web 与小程序共用本后端**：接口约定对齐 V3 Admin Vite（Web）与微信/抖音小程序（miniapp-login），前后端开箱即通。

## 一、环境要求

- JDK 21、Maven 3.6+
- MySQL（默认配置连本地库；若只测登录可暂不建库，登录用内存账号）
- 前端开发服务指向本服务 8080 端口

## 二、启动项目

```bash
# 1.（可选）建库建表：执行 sql/init.sql（创建 skeleton 库和示例表）

# 2. 改数据库连接：src/main/resources/application.yml 的 datasource

# 3. 启动
mvn spring-boot:run
# 或 IDE 运行 com.skeleton.SkeletonApplication

# 4. 验证：浏览器访问 http://localhost:8080/api/v1/auth/captcha（返回占位图即正常）
#    或先登录拿 token：POST /api/v1/auth/login
```

**内置演示账号**：admin / 123456（Web 内存校验，无需数据库即可登录，接真实用户表后替换 AuthController 逻辑）；小程序登录用 `POST /api/v1/auth/miniapp-login`（骨架模拟，见下）。

**Web 与小程序共用说明**：
- Web 前端（V3 Admin Vite）调 `/api/v1/auth/login`、`/api/v1/auth/captcha`、`/api/v1/auth/info`
- 小程序前端（微信/抖音）调 `/api/v1/auth/miniapp-login`（入参 `{code, platform}`，platform 为 wechat/douyin，返回 `{token}`）
- 骨架阶段小程序登录为**模拟**（不真调平台 code2session，用 code 直接发 token）；接真实平台时在 AuthController.miniappLogin 中替换为平台 code2session 调用（代码注释已给出微信/抖音接口地址）

## 三、目录结构

```
后端/
├─ pom.xml                  # 依赖（Web/Validation/MyBatis-Plus/JWT/Lombok）
├─ sql/init.sql             # 示例表建表脚本
└─ src/main/java/com/skeleton/
   ├─ SkeletonApplication.java   # 启动类
   ├─ common/               # 公共：Result（统一响应）、BusinessException、GlobalExceptionHandler、JwtUtil
   ├─ config/               # 配置：MybatisPlusConfig（分页插件、Mapper 扫描）
   └─ modules/              # 业务模块（按业务分包）
      ├─ auth/              # 登录鉴权（对齐前端约定）
      └─ demo/              # 示例模块（新业务复制它的结构）
```

## 四、模块内分层（以 demo 为例）

```
controller/   # 接口入口：@Valid 校验入参，返回 Result
service/      # 业务逻辑（接口 + impl 实现）
mapper/       # 数据访问（继承 BaseMapper 即得单表 CRUD）
domain/       # 实体（Bo=入参、Vo=出参、实体类=表映射）
```

**硬性约定**（知识库规范）：
- 入参用 **Bo**（带校验注解），出参用 **Vo**，**不直接返回 Entity 给前端**
- 统一返回 `Result<T>`（code=0 成功），业务失败抛 `BusinessException`
- 参数校验失败/业务异常/未知异常都由 `GlobalExceptionHandler` 统一处理，Controller 不写 try-catch

## 五、怎么加一个"新模块"（最小路径）

1. **复制 demo 模块**改名为业务名（如 order → controller/service/mapper/domain 四层）
2. **建表**：在 `sql/init.sql` 加建表语句（表名 snake_case，含 deleted/create_time/update_time）
3. **写实体**：`@TableName("order_item")` 映射表；Bo/Vo 定义入参出参
4. **写 Mapper**：继承 `BaseMapper<实体>` 即完成单表 CRUD
5. **写 Service**：接口 + impl 实现业务逻辑，校验失败抛 `BusinessException`
6. **写 Controller**：RESTful 接口，返回 `Result`，路径前缀 `/api/v1/{模块}`
7. **前端对接**：按"接口约定"一节的前端格式对接

## 六、接口约定（与前端契约，勿改）

- 响应：`{ code, data, message }`，**code=0 成功**
- 鉴权：前端自动带 `Authorization: Bearer <token>` 头（axios/request 封装）；后端从 header 解析（见 AuthController.info）
- 401：**token 缺失/无效/过期 → 返回 HTTP 401**（全局异常处理统一处理；前端据此跳登录）

## 七、配置说明

- 端口：8080（application.yml `server.port`）
- JWT：`jwt.secret` / `jwt.expire-hours`——**生产环境必须更换 secret**
- 逻辑删除：实体含 `deleted` 字段即自动逻辑删除（MyBatis-Plus 配置已开）
- 分页：`new Page<>(pageNum, pageSize)` 传入 service，返回 `Page<Vo>`（含 total/list）
