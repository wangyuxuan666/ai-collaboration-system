# 纯净骨架 — 框架说明书（技术经理选型用）

## 是什么

一套**不带业务模块**的工程骨架：只有规范的地基（目录结构、请求封装、路由守卫、分层代码），没有用户/角色/菜单等现成后台功能。拿到就能写业务，业务形态自由。

## 技术栈

- 后端：Spring Boot 3.5 + JDK21 + MyBatis-Plus + JWT 鉴权
- 前端：Vue3 + Vite + TS + Element Plus + Pinia（[V3 Admin Vite](https://github.com/un-pany/v3-admin-vite)）
- 数据库：MySQL（后端默认配置）
- 前后端可独立开发：前端配好接口地址即可联调，后端先跑演示账号

## 有什么

- 前端：目录约定（apis/pages/pinia/router）、请求封装（axios 拦截器）、路由守卫、权限指令、AI 协作规则（自带 AGENTS.md）
- 后端：分层结构（controller/service/mapper/domain + bo/vo）、统一响应、全局异常处理、登录鉴权（JWT）、分页、示例业务模块
- 前后端已按同一接口约定实现，登录链路实测联通（admin/123456）

## 能达到什么效果

- 非后台类项目免去从零搭工程：结构规范、约定清晰，AI 直接写业务
- **AI 写出的代码统一、好维护**：前端有 AGENTS.md 指导 AI，后端分层和命名约定写在示例里
- 骨架轻，可删可加，不像全套框架带冗余

## 适合

- 官网、展示站、工具站、单页应用、小型业务系统
- 不需要登录/权限后台，或只需要极简登录的项目

## 不适合

有完整后台管理需求（多用户、角色权限、管理列表）的项目——用"若依Plus全配"方案，别在骨架上重造。

## 选型建议

项目**不像后台管理**（无复杂权限、无管理后台）→ 推荐本方案。给客户的话术："推荐选**纯净骨架**，理由：项目不需要复杂的后台权限体系，骨架更轻、开发更快，符合项目实际规模。"

## 落地方式

复制 `前端\`、`后端\` 到新项目根 → 前端 `pnpm i && pnpm dev`；后端按说明书启动（配数据库或先跑 Mock）→ 改项目名 → 写业务。

## 官方资料

- 前端源项目：[un-pany/v3-admin-vite](https://github.com/un-pany/v3-admin-vite)（中文文档在掘金专栏"V3 Admin Vite"）
- 接口约定：`{code, data, message}`，code=0 正常；Bearer token 鉴权；401 跳登录（前后端已按此约定实现并实测联通）
- 协议：前端 MIT；后端为自搭骨架，无外部协议约束
