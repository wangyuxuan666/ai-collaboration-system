# 前端开发说明书（V3 Admin Vite）

> 纯净骨架的官方前端：Vue3 + Vite + TS + Element Plus + Pinia，AI-friendly 模板。
> 项目自带 `AGENTS.md`（AI 编码规则，开发 AI 必须遵守）和 `.agents/skills`。

## 一、启动项目

```bash
pnpm i        # 装依赖
pnpm dev      # 启动开发服务（默认 3333 端口）
```

- 环境配置：`.env.development`（含 `VITE_BASE_URL=/api/v1` 后端路径前缀）/.env.production
- **无 Mock**：接口直连后端（`.env.development` 的 `VITE_BASE_URL` 指向后端地址，或配代理）
- 后端演示账号 admin/123456 已按前端约定实现，启动后端即可登录

## 二、目录结构（src/）

| 目录 | 放什么 | 开发时动作 |
|---|---|---|
| `common/apis/` | **通用接口**（多页面共用的），按业务分目录（users/tables...），每模块 `index.ts`+`type.ts` | 共用接口放这里 |
| `pages/` | 页面组件（dashboard/demo/login/error...）。**页面私有代码收拢在页面目录内**（如 `pages/login/apis`、`pages/login/components`） | **加页面：** 在 `pages/` 下新建目录，私有接口/组件/函数都放页面目录内 |
| `http/axios.ts` | axios 封装（拦截器、token、错误处理） | 一般不改，直接调 apis 层 |
| `router/` | 路由：`config.ts`（路由表）、`guard.ts`（守卫）、`whitelist.ts` | **挂路由：** 在 `config.ts` 加 |
| `pinia/stores/` | Pinia 状态（user/app...） | 全局状态放这里 |
| `common/components/` | 通用组件 | 可复用组件放这里 |
| `common/composables/` | 组合式函数（hooks） | 复用逻辑放这里 |
| `common/utils/` | 工具函数 | 按需使用 |
| `plugins/` | 全局插件（权限指令、svg 图标等） | 一般不改 |
| `layouts/` | 布局组件 | 一般不改 |

**核心约定：同一个业务逻辑的代码和资源收拢到一起**——页面私有接口放页面目录，不散落到 common（登录模块接口在 `pages/login/apis`，不在 `common/apis`）。

## 三、怎么加一个页面（最小路径）

1. **加接口**：页面私有接口 → 页面目录下建 `apis/`；通用接口 → `src/common/apis/xxx/`
2. **加页面**：`src/pages/xxx/index.vue` 写页面
3. **挂路由**：`src/router/config.ts` 加路由（含 `meta.title`、`meta.requiresAuth` 等）
4. **页面里调接口**：`import { listXxx } from '@/common/apis/xxx'`（或页面内 apis）

> 参考现有 `pages/demo` 和 `pages/login` 的写法，保持一致。

## 四、权限控制

- 路由守卫：`src/router/guard.ts`（未登录跳登录页）
- 登录态：`src/pinia/stores/user.ts` 存 token
- 页面级权限：路由 `meta` 配置；按钮级：`v-permission` 指令（`plugins/permission-directive.ts`）

## 五、接口约定（与后端契约）

- 响应格式：`{ code, data, message }`，**code=0 成功**
- 鉴权：请求头 `Authorization: Bearer <token>`
- 401：后端返回 401 → 前端自动回登录页
- 后端已按此约定实现（见后端说明书），对接即通

## 六、AI 开发须知

- **必须遵守项目根 `AGENTS.md`**：编码前思考、简洁优先、精准修改、目标驱动——这是本项目"AI 写出规范代码"的核心机制，开发 AI 先读它再动手
- 匹配现有代码风格，不引入未要求的抽象
