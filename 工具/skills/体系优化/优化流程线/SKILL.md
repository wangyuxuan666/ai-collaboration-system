# 优化流程线（Skill · 通用版）

> 本 skill 属于「体系优化」系列，只负责**优化一条具体流程线**，不覆盖协作体的全部优化场景。体系优化可能还有其它 skill，本 skill 只处理"选一条线，按方针排查并优化"。

## 触发

- 本 skill 仅在**用户点名使用本 skill、或在询问方式时明确选定本 skill** 后读取执行。用户已明确本次做法且未点名本 skill 时：不读取、不再问方式，直接按用户说明执行（判定见[维护方针](../../../../协作入口/AI协作体系维护/AI协作体系维护方针.md) Skill 索引）。用户表达优化意愿但未定做法时，按维护方针 Skill 索引先问方式（本 skill 可作为候选之一），用户选定后才进入本 skill 流程。
- 触发边界：用户提到优化、修改、整理、评价某条线或某个文件 → 按维护方针 Skill 索引判断：用户已明确做法且未点名本 skill → 不读本 skill、不问方式；未定做法 → 问方式时可把本 skill 列为候选；用户点名或选定本 skill 后才进入本 skill 流程。
- 平台调用方式（各平台加载不同）见本平台的 [skills接入.md](../../../../协作入口/Agent适配/README.md) 指引。

## 前置

- 先读取本平台的[入口规则](../../../../协作入口/Agent适配/README.md)（平台特有规则）与[Agent 适配入口](../../../../协作入口/Agent适配/README.md)（公共规则）。
- 相关规范以协作体[协作入口](../../../../协作入口/README.md)的必读链为权威，本 skill 不重复改写规则。

## 流程

### 1. 选线
由用户输入要优化的线（如"角色""成长""知识库"或其它，未来可能新增）；用户未明确时，根据其表达判断或询问。AI 不预设线的清单，按用户输入查找对应目录与文件；线的边界（主目录 + 其规范/入口/被引用方）由 AI 自行判断——既然是优化 AI 协作体，读取目标线是必要动作，自行判断即可。

### 2. 读线 + 读方针
- 列出目标线全部文件，绘制引用关系图（谁链接谁、谁被谁引用）
- 读取维护方针，以核心理念、关键概念、协作方式为判断标准

### 3. 排查（按方针逐条对照，按以下顺序依次检查，避免遗漏）
1. 结构：越级平铺（子级出现在不该出现的一级入口）、重复引入（同一内容多处出现、入口与辅助职责重叠）
2. 路径：断链（引用失效）、绝对路径（硬编码，迁移后失效）
3. 职责：孤章（被引用文件章节无入口引用）、职责不清（入口过重 / 管理规范冗余 / 工具内部实现写进文档）

### 4. 结论与建议 → 确认 → 修改
- 汇总排查发现的问题与修改建议，向用户说明
- 直接问"是否开始修改"，由用户判断；用户确认后动手
- 整线处理：文件、索引、规范、流程、工具、引用一次性清理干净

### 5. 模拟测试
- 假装自己是一个只会按字面执行、不会自己联想的新 AI，把这条线的流程完整走一遍（如"读入口→查记忆→新增→修正→反馈"），看哪里会卡住或需要靠猜。
- 卡住或靠猜的地方，就是规则没写明白的地方——把隐含规则补写清楚，让"笨 AI"也能照着走对。
- 最后检查引用是否完整、相对路径是否都能找到目标、有没有残留的绝对路径。

## 反哺方针

排查与优化过程中，用户可能提出新概念、新偏好或新规则。AI 自行判断：它是否属于优化协作体的通用方法（适用所有线）——是则反哺进维护方针（核心理念 / 关键概念 / 协作方式）；只属于当前线的机制实现则留在当前线。

## 协作偏好

- 先懂再动：完整理解线结构与引用后再提方案
- 主动挖需求：不被动"用户说哪改哪"；主动分析意图与影响，提出用户可能没想到的
- 改前确认：对齐方案、用户说停必须停
- 一次一个问题；给选择时带权衡（优缺点与核心理念挂钩）
- 验证收尾：改动后核对引用、路径、行为未破坏体系
