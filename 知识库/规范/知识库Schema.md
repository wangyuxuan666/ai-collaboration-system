# 知识库 Schema

## 1. 作用与边界

本文件是知识库的数据结构唯一说明，定义目录、文件类型、metadata、引用和同步关系。模板和检查工具必须与本文件一致；角色规则和任务流程只定义何时读取、提交、确认和执行，不重复定义字段。

收集箱、raw、Wiki 分别是待处理候选、可追溯来源和可复用结论层。项目专属约定不进入全局 Wiki。

## 2. 目录与关系

```text
收集箱/收集区
收集箱/手动收集区
收集箱/暂存区
收集箱/已处理
  → 经用户确认处理
raw/<来源类型>/<专业领域>
  → 提炼或更新
./Wiki/<专业领域>/<主题路径>/知识
```

- 对话候选进入收集区；用户手动投放的文件或文件夹进入手动收集区。
- 暂存区保存候选或来源暂时无法决定归属、等待进一步确认的内容，不参与读取或检索。
- 已处理区保存已转 raw、仅归档或已废弃的原始投放文件副本，处理结果记录在处理记录中；已处理区不作为读取来源。
- 来源类型按来源渠道按需创建（如对话候选、手动收集、本地旧知识库），不预建空目录；raw 附件归档在 `raw\assets\<来源类型>\<专业领域>\附件\`，由 raw 的 `附件路径` 字段引用。
- 一份 raw 可支持零到多篇 Wiki 页面；一篇 Wiki 页面可由多份 raw 支持。
- 知识页必须登记在[知识索引](../Wiki/index.md)；角色行为规范由角色体系管理，不登记在知识库。
- 收集箱处理记录和 Wiki 日志均只追加。

## 3. 收集候选

文件名：`KB-YYYYMMDD-NNN_主题.md`。

```yaml
类型: 知识候选
候选编号: KB-YYYYMMDD-NNN
提交日期: YYYY-MM-DD
提交者: <角色或无>
来源任务: <任务 ID 或无>
专业领域: 待管理员判断
主题: []
```

正文必须有：`候选结论`、`来源与证据`、`适用条件与疑问`。手动收集区来源不要求此格式。

## 4. raw 来源记录

```yaml
类型: 原始来源
来源名称: <名称>
来源链接或路径: <URL 或本地路径>
收集日期: YYYY-MM-DD
来源任务: <任务 ID 或无>
提交者: <角色或无>
专业领域: <专业领域>
主题: []
脱敏: <无 / 已脱敏，说明>
处理状态: <待提炼 / 已提炼 / 仅归档 / 待确认>
关联Wiki页面: []
原收集项: <收集区路径或无>
附件路径: []
```

raw 正文和附件归档后不得改写来源事实；处理状态、关联 Wiki 页面等管理字段可以更新。`关联Wiki页面` 与 `附件路径` 使用相对知识库根目录的路径并统一使用 `/`。

## 5. Wiki 知识页

```yaml
类型: 知识
启用: 是
范围: <专业领域/主题路径>
来源: []
```

正文固定为：`结论`、`触发条件`、`做法与验证`、`适用条件与边界`、`证据与演变`、`相关知识`。

## 6. 索引与日志

知识索引按专业领域分组，每条格式为：`- [页面标题](相对 Wiki 的路径)｜任务关键词｜一句任务场景摘要｜来源×N（更新 YYYY-MM-DD）`，只登记启用的知识页。`来源×N` 中的 `N` 为知识页 `来源` 字段数量；更新日期取知识页“证据与演变”或维护日志中该页最近变更日期，用于判断页面成熟度（多来源交叉印证）与新鲜度。

[收集箱处理记录](../收集箱/处理记录.md)记录每批处理结果与目标路径或理由。[Wiki 维护日志](../Wiki/log.md)记录 raw 到 Wiki 的正式变更，只追加不重写；新条目以 `## [YYYY-MM-DD] <类型>｜<页面或范围>` 标题行开头，详情写在标题下，便于用 `grep "^## \["` 按时间线检索。

## 7. 校验

- 对话候选必须有唯一候选编号和完整必填字段。
- Wiki 页面路径、类型、范围和启用状态必须一致。
- 启用知识页必须有来源、index 条目和 log 记录。
- raw 的关联 Wiki 页面和知识页的来源必须指向真实文件。
- 模板、检查工具和其他规则中不得重复定义与本文件冲突的字段。
