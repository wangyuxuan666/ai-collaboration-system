# 记录分流入口

本入口只判断发现的问题、错误与结论是否需要长期记录、进入哪个入口，或是否该建议修改协作体；具体写入方式由目标入口规定。

## 分流

发现问题、犯错或形成可复用结论的当下（含发现规则/文件/职责缺口），在该动作告一段落后即读本入口判断去向；不得自行消化、只记在心里，或拖到整个任务完成才处理。
**向用户提出任何"建议记一条/挪个库/改体系文件"的候选之前，先按本入口判断去向**（该记经验/知识的记，该建议改规则的建议），不得未经分流直接把候选抛给用户。
**纠正反应协议（硬触发）**：触发不是"我觉得有料才分流"，以下任一信号出现即必须走本流程——① 用户纠正你、说你错了、或同一点又说了一遍（对象可以是本窗口的动作，也可以是别的窗口/历史动作，同样按信号触发）；② 你自己发现刚才做错了或漏了什么；③ 用户指出"你没分流 / 又忘了 / 没先问 / 没分流 / 直接做了 / 先想想该记哪"。收到信号先停、立即补走本流程：拆条判断去向（该记的记、该建议改规则的提出；去向为 画像 / 经验 / 知识收集区 / 建议改体系 / 仅当场修正不用记），再回应用户；**回应用户时把归类说出来**（"这条归 X、记进 Y / 建议改 Z，待你确认"），让"记没记、记对没"当场可查；不辩解、不口头承认后就翻篇、不把补分流拖到任务结束。
先把同一事件中的不同内容拆开，再逐条判断：

- 关于用户本人，且所有窗口都适用的稳定信息或全局协作偏好，读取[用户画像维护规则](../../自成长/用户画像/维护规则.md)。
- 关于 AI 在特定任务、角色、阶段或场景中如何行动的偏好、做法和教训，读取[经验维护规则](../../自成长/经验/维护规则.md)。
- 同类问题反复出现、现有规则/职责/文件约束不住，或事件暴露了协作体结构缺口（公共规范、角色文件、模板、流程、节点模板等）时，**不默认只进经验了事**：先向用户提出修改建议（改哪个文件、怎么改、影响谁、由谁改），用户拍板后按[协作体维护方针](../AI协作体系维护/AI协作体系维护方针.md)执行；普通角色窗口只提建议、不擅改协作体文件。与[经验入口](../../自成长/经验/入口.md)"空白处理闭环"的分工：空白闭环管当前任务缺信息时怎么问、怎么记；本入口管发现与教训沉淀到哪、是否该动规则；同一事件合并成一次提问，不重复打扰用户。
- 关于客观对象的事实、专业方法、技术规律，或可由不同执行者共同遵守的专业规范，读取[收集箱入口](../../知识库/收集箱/入口规则.md)。
- 明确只影响当前任务，且不会帮助以后判断或行动的内容，不长期记录。

同一条内容只进入一个入口；同一事件可以拆出多条内容，分别进入不同入口。密码、令牌、私钥、密钥及其他可直接使用的敏感值不得长期记录。

同一条内容看起来同时符合两个入口，或无法判断适用范围时，读取[记录分流案例](./案例.md)；参考后仍无法可靠判断，再询问用户。
