# 上下文管理规范

## 1. 适用范围

本规范适用于所有对话、角色和任务。它管理当前任务需要带入的最小信息，不替代其他专用规范或具体任务流程。

## 2. 核心原则

- 当前任务只携带完成当前判断所需的最小上下文。
- 历史对话、规则、自成长、知识、原始证据和任务状态不是同一类信息，应按用途分开处理。
- 已确认的结论、未解决的问题和下一动作应保持在当前上下文前沿；无关历史降为按需查询的资料。
- 上下文卡是临时任务状态，不是自成长或知识库内容，不自动写入自成长、`raw`、Wiki 或其他长期文件。

## 3. 最小上下文卡

复杂任务或任务阶段发生变化时，建立或更新一份简短上下文卡，至少包含：

- 当前目标；
- 当前范围与明确排除项；
- 已确认事实、决定和授权；
- 未解决问题、风险或证据缺口；
- 下一动作与完成条件。

上下文卡只保留当前有效状态。被新决定替代的内容移入历史记录或保留来源指针，不继续占用当前上下文。

## 4. 动态触发

- 不在对话开始时固定判断任务规模；随着任务推进持续评估上下文负担。
- 优先在目标或阶段变化、未决事项增多、反复引用早期内容，或当前判断开始依赖过长历史时建立或更新上下文卡。
- 建立节点、接手复杂任务或跨窗口交接时，应建立或更新最小上下文卡。
- 如果平台提供可靠的上下文用量，在接近上下文容量的约 40%～50% 时进行压缩，给后续回答保留空间。
- 如果无法获得可靠 Token 用量，以约 8～10 轮实质对话作为检查兜底；简单确认不计入，完成阶段压缩后重新计数。

## 5. 按需加载

- 全局规则只提供稳定边界；角色、专业领域、流程、自成长、知识和证据按当前任务命中情况加载。
- 先使用索引、摘要、状态和来源指针定位信息，只有其内容可能改变当前判断时才读取正文。
- 自成长先按当前任务动作、阶段、模块和关键词通过 agentbrain 检索记忆（`agentbrain query`），只读取可用且命中的少量记忆；证据不足或影响范围扩大时再补充检索。
- 不因存在双链、历史对话或相关文件而递归加载全部内容。
- 跨对话传递任务时，只传递上下文卡、必要交付物入口、验证证据和风险摘要，不默认复制完整聊天记录。

## 6. 压缩与恢复

- 当对话变长、任务阶段切换或当前目标发生变化时，先压缩已有讨论，再继续处理。
- 压缩结果应保留决定、依据、适用条件、未决事项和恢复入口，不以脱离来源的结论替代证据。
- 上下文卡不能改变用户已确认的目标、范围、验收标准、权限或协作边界；发生实质变化时重新确认。
