# MCP 与 Skill 接入规范

## 适用范围

协作体新增或接入 MCP、skill 时的统一规则，覆盖存放、说明书、平台接入与验证。

## 核心原则

- 协作体工具（MCP 服务、skill）源码存放在协作体，平台不持有源码。
- 说明书按需加载：平台自动注入的内容压到最小，详细用法写协作体文档，用到时才读；不用的工具不占上下文。

## 存放

- MCP 源码：`工具\MCP\<名称>\`
- skill：`工具\skills\<名称>\`（含 SKILL.md 与运行所需文件）
- 登记：MCP 在[工具/MCP/README.md](../../工具/MCP/README.md)，skill 在[工具/skills/README.md](../../工具/skills/README.md)

## 说明书

- 详细用法写入协作体文档，格式统一为三列：工具 | 用途 | 参数怎么填（标注必填/可选/默认值，必要时给例子）。
- 使用规则写明"什么场景用到哪个工具"；用时按规则读取说明书，不用的工具不读。

## MCP 接入

- 平台自动注入的工具 schema 压到最小：清空工具 description（保留参数名/类型/必填）。
- 平台支持工具过滤时（如 Gitee 的 `ENABLED_TOOLSETS`），只暴露实际使用的工具。
- 接入配置与验证按各平台 `MCP接入.md` 执行；接入后以一次只读调用验证。

## Skill 接入

- 平台默认的技能自动注入对协作体技能关闭：禁用平台技能注入插件（如 DSH 的 `tool-skill`）。
- 技能触发：协作体规则写明"什么场景用哪个技能、`read` 哪个 SKILL.md"；执行按 SKILL.md 步骤；同一窗口已读过的 SKILL.md 不重复读，未读过才 read。
- 使用点就近：单一使用点的 skill，SKILL.md 路径直接放在使用点文档的触发条件旁（如优化流程线在[维护方针 Skill 索引](../AI协作体系维护/AI协作体系维护方针.md)、UIUXProMax 在[界面实现流程](../../角色/角色列表/软件研发/开发/前端/前端开发/流程/界面实现.md)）；多使用点或含多个子 skill 的 skill（如 UA）集中登记场景表在 `工具\skills\README.md`，各使用点注明"用时先 read UA 场景表"。不设覆盖全部 skill 的集中触发表。
- skill 需要运行环境时（插件/依赖），在对应技能目录说明准备方式，按需安装。

## 新增流程

1. 源码放入对应目录。
2. 登记（`工具/MCP/README.md` 或 `工具/skills/README.md`）。
3. 写说明书（三列表格 + 触发规则）。
4. 平台接入（最小化配置）。
5. 验证（MCP 一次只读调用；skill 按 SKILL.md 触发执行）。
