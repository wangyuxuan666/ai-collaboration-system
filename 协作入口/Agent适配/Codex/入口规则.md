# Codex 入口规则

本文件只记录 Codex 平台的运行规则，并路由到按需接入文件。

## 身份与任务

- **独立任务**：只有实际创建且可定位的 Codex 任务，才作为独立任务登记；内部子 Agent 不登记为独立任务。
- **任务创建**：只有用户明确要求时，才创建用户可见的独立 Codex 任务。
- **身份与核验**：独立任务使用平台实际任务 ID 登记；内部子 Agent 不自动获得核心角色身份或更高权限，其结果必须通过实际交付物核验。

## 委派与子任务

- 当前任务内有限、可独立判断的子任务，可交给内部子 Agent 承接；内部子 Agent 不登记为独立任务。

## 接入硬性检查点
- 需要调用 MCP、skill 或浏览器控制能力时，先检查当前会话是否真实出现对应工具；插件链接、标签提及或工具名称本身不算可用。工具存在才继续任务；工具不存在按[工具接入与故障处理 SOP](../README.md)处理，恢复期间暂停依赖该工具的主体任务，但继续执行允许的恢复动作。
- 工具调用失败后，同一故障原因不得无新证据地重复尝试；出现新证据或进入新的恢复阶段时，可以继续排查、接入和验证。
- 需要调用已登记 MCP，但工具未出现或调用失败时，必须按[工具接入与故障处理 SOP](../README.md)执行；具体参数见 [MCP接入](./MCP接入.md)。完成接入或按 SOP 暂停前，不得继续任务，不得静默跳过，不得用 CLI 或脚本冒充 MCP。
- 需要调用已登记 skill，但缺失、断链或未发现时，必须按[工具接入与故障处理 SOP](../README.md)执行；具体参数见 [skills接入](./skills接入.md)。完成接入或按 SOP 暂停前，不得继续任务，不得静默跳过或使用替代流程。
- 未触发时不读取、不检查。

## 恢复

- 核对 Git 基线、环境、依赖和权限（Codex 平台不自动保留这些状态）。
- 优先使用平台实际任务 ID 定位任务。
