## 工具接入与故障处理 SOP（各平台通用）

触发：每个动作开始前先核对该动作依赖的所有已登记 MCP/skill；若任一必需 MCP/skill 未出现或调用失败，立即按下方 SOP 执行，不得静默跳过、降级替代或继续执行依赖该 MCP/skill 的主体动作；完全不依赖 MCP/skill 的动作不触发检查。

1. **排查并恢复**：先读当前平台的 `MCP接入.md` / `skills接入.md`，再按说明核查本地源码、可执行文件、依赖、配置和环境变量。不得自行搜索、猜测路径或重复下载已存在的工具；协作体已提供的源码必须复用固定路径。只有确认本地资源确实缺失时，才读取对应安装指引（MCP 用 `工具/MCP/安装指引.md`、skill 用 `工具/skills/安装指引.md`）准备外部资源。
2. **分支处理**：
   - 本地已有工具但未注册、未连接 Codex 或未生效 → 复用本地工具，按当前平台接入文件注册或修复配置，并按文档验证；
   - 协作体规定路径缺少源码 → 判定为协作体文件不完整，报告缺失项并暂停；不得自行搜索其他副本、下载源码或安装第二份；
   - 本地确实缺少依赖或外部工具 → 按安装指引自动准备、下载或安装，并验证结果；只有出现必须用户完成的动作（如重启 Codex、登录、权限或交互式授权）时，才说明具体动作、影响和验证方式，向用户提出申请。申请前不得停在“请用户自行排查”或让用户独自完成整套安装。
   - 上述步骤需要重启平台或更高权限的，也先自动完成可执行部分；到达必须由用户完成的临界步骤时再提出申请。
3. **验证**：工具真实出现且成功调用才算完成；CLI 或脚本可运行不等于已接入。
4. **兜底**：自动恢复失败时，说明失败项、已尝试动作、阻塞原因和下一步；仅在确实需要用户动作时暂停并等待用户完成。不得静默跳过或用替代流程冒充。恢复期间暂停依赖该工具的主体任务，但继续执行本 SOP 允许的排查、准备、安装、修复和验证动作。
