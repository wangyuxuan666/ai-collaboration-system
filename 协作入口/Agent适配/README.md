## 工具接入与故障处理 SOP（各平台通用）

触发：需要使用已登记 MCP/skill，但工具未出现或调用失败时，按下方 SOP 执行；未触发时不检查。

1. **排查**：先读当前平台的 `MCP接入.md` / `skills接入.md`。按接入文件给出的固定路径和命令判断原因；不得自行搜索、猜测路径或重复安装已随协作体提供的源码。只有接入文件判断缺少依赖或外部工具时，才读取对应安装指引（MCP 用 `工具/MCP/安装指引.md`、skill 用 `工具/skills/安装指引.md`）。能直接接入现有源码的，继续完成，不拿半成品问题问用户。
2. **分支处理**：
   - 协作体已提供源码但未注册/未生效 → 按当前平台接入文件直接注册或修复配置，并按文档验证；
   - 协作体规定路径缺少源码 → 判定为协作体文件不完整，报告缺失项并暂停；不得自行搜索其他副本、下载源码或安装第二份；
   - 缺少依赖或外部工具 → 先说明要安装什么、安装到哪里、影响什么、如何验证，并征得同意后再安装；
   - 上述步骤需要重启平台或更高权限的，也先说明影响和验证方式并征得同意后执行。
3. **验证**：工具真实出现且成功调用才算完成；CLI 或脚本可运行不等于已接入。
4. **兜底**：失败时说明失败项、修复成本、替代方案，暂停等用户决定；不得静默跳过或用替代流程冒充。恢复期间暂停依赖该工具的主体任务，但继续执行本 SOP 允许的排查、接入和验证动作。
