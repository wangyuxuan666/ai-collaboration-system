## 工具接入与故障处理 SOP（各平台通用）

触发：需要使用已登记 MCP/skill，但工具未出现或调用失败时，按下方 SOP 执行；未触发时不检查。

1. **排查**：先读当前平台的 `MCP接入.md` / `skills接入.md`（接入参数）与对应安装指引（MCP 用 `工具/MCP/安装指引.md`、skill 用 `工具/skills/安装指引.md`，含本地源码与装法），按文档判断原因并找出能自己完成的部分——本机没装？还是装了但未链接/未生效？（判断"没装"**必须先做本地核查**：命令/PATH、包管理器全局安装、协作体本地源码与现成产物，不能凭印象下结论）**能按文档自己接入、自己装好的，直接完成，不拿半成品问题问用户。**
2. **分支处理**：
   - 没装 → 按安装指引安装（协作体有本地源码或现成装法时优先照做）；第三方 CLI 先查其支持的环境变量重定向（避免官方脚本默认写 C 盘、改注册表/PATH），落点与用户确认后手动安装；装完验证命令可用（优先用工具自带诊断，如 bsk doctor）；
   - 装了但未链接/未生效 → 按当前平台 `MCP接入.md` / `skills接入.md` 的接入方式配置，按文档验证生效（如 DSH 配置热重载）；
   - 上述步骤里**需要下载、安装、修改平台配置、重启平台或更高权限**的，先向用户说明"装什么/改什么、装到哪、影响什么、如何验证"并征得同意后再执行。
3. **验证**：工具真实出现且成功调用才算完成；CLI 或脚本可运行不等于已接入。
4. **兜底**：失败时说明失败项、修复成本、替代方案，暂停等用户决定；不得静默跳过或用替代流程冒充；未完成接入或未暂停前不得继续原任务。
