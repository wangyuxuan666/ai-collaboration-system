# AI 协作体系维护方针

优化、修改、整理或迁移协作体系时，先读本方针。

## 核心理念

1. **完美嵌套**：体系对新 AI 对话应逐环节向下嵌套，无冲突、无重复、无无用内容，每一步都对当前环节有帮助。
2. **token 节省、精准化开发**：长期以最少的 token 和沟通成本设计结构、规则和流程，精准达成目标；能一句说清不写两句，能一次到位不来回返工。
3. **树形组织**：体系按树形分层，入口文件是一级，向下逐级展开；子级从各自入口进入，不越级平铺、不互相乱链。
4. **最小上下文**：每个环节只携带当前判断所需信息，不因“可能相关”全量加载，需要更多依据时再扩大范围。文件也只保留读者执行当前动作所需信息，不写入读者不需要的工具实现或存储细节。
5. **触发式加载**：非必要内容以触发条件驱动，未触发不读取；"必读"仅限每个场景都无法回避的内容。
6. **职责单一**：一个文件只承担一种职责；共用内容上收，角色、平台或任务差异下分。
7. **唯一权威**：同一规则只保留一个权威来源，其他文件只引用，不重复改写。
8. **绑定使用者**：每份规则或资产都有明确的使用方与进入方式，谁用谁引；无主内容或跨线乱引是结构缺陷。
9. **整线一致**：调整一个机制时，其关联的所有环节（文件、索引、规范、流程、工具）同步调整，不留残余。
10. **协作者而非流水线**：规则明确职责、边界、确认和验收，不替代角色的专业判断或规定每一步；把 Agent 当作能理解和判断的协作者，发现问题时提出反驳和替代方案，不为反驳而反驳。
11. **主动审视合理性**：优化协作体系时不机械维护现状；在理解目标和现有设计后，主动检查结构、职责、流程和表达是否合理，发现不必要、重复、绕行或增加成本的设计时提出更合适的方案。
12. **强制可读性与可执行性**：协作体中的规则、流程、节点任务和交付文档，必须使用直白、具体、可执行的语言。禁止为了显得专业而堆砌高大上词汇、抽象概念、自造术语或包装性表达。凡是后续 AI 不能据此直接判断“做什么、不能做什么、下一步做什么”的内容，不得写入正式文件，必须改写、删除或下沉。文件作者必须站在后续 AI 的读取和执行角度逐句检查，不能以作者自己“看得懂”为合格标准。
13. **控膨胀**：规则与资产按实际使用生长，不为未发生的问题提前建文件；新增前先复用现有，低使用内容优先归档瘦身。体系是长出来的，不是设计出来的。

## 关键概念（语义化解释）

- **必读**：每个场景都无法回避的内容，无条件读取，通常位于入口文件。
- **按需**：死规定；触发条件必须明确，命中时**必须读**，未命中**不读**，AI 无裁量权。
- **参考**：不属于规则，AI 可根据实际情况自行判断是否使用，如教学示例、模拟流程。
- **入口文件**：树的节点，负责路由。一级入口只放主干与必读内容；子级从各自入口进入。
- **引入 vs 定义**：入口引用其他文件是“引入”（路由）；规范内指名存储位置或文件是“定义”（规则本身），不可混淆。
- **引用跟触发点走**：不设独立的导航/相关文档表；引用直接放在实际触发动作的位置，触发条件旁就是该读的文档。
- **相对路径 + 超链接**：文件间统一用 Markdown 超链接 `[名称](相对路径)`，不用绝对路径，以免协作体搬迁后失效；同级子目录显式使用 `./`，上级目录使用 `../`，不省略路径起点。顶部可集中一处路径索引，正文引用只写链接。
- **入口=核心，管理=辅助**：入口文件是每次会话必读的核心操作手册；辅助判断与详情下沉到管理/规范文件，入口单向引用它（`[管理规范](路径) 章节号`），不反向依赖。
- **无孤章**：被入口引用的辅助文件，其每个章节都必须有入口引用；没有引用入口的章节要么删除、要么找合适位置引用，不得成为 AI 永远读不到的孤儿内容。
- **入口精简**：入口只放触发与运行必需内容，详情、索引、示例下沉；需要时经入口引用进入。

## 协作方式

1. **先懂再动**：理解体系结构、文件职责和相互引用后再提方案，不只看目录或文件名就下结论。
2. **协作体建议检查**：用户的想法和要求是需求来源，不直接视为最终方案。用户讨论、评价、设计、优化或修改协作体时，先确认目标和范围，再按[语义检查清单](../规范/语义检查清单.md)从新窗口首次读取、触发与下一步动作、重复与冲突、遗漏与风险、必要 token 方面一次性检查；命中专项问题时才读取对应规则。同一方案连续讨论不重复检查，目标、范围或方案发生实质变化时再检查。发现更合适的结构或表达时直接提出理由和替代方案，不机械照搬用户原话；对外只给结论、依据、风险和推荐方案，不逐项展示检查过程。
3. **改前确认**：动手前先对齐方案，确认后再改；修改体系规则或机制前，先按编号或关联经验查[档案](./档案/README.md)该规则的历史；用户说"先别动/等我说动手"时必须停下。
4. **整线处理**：涉及一个机制时，从文件、索引、规范、流程、工具到引用一次性清理干净，不留碎片。
5. **验证收尾**：修改后核对引用、路径和实际行为，确认没有破坏原有体系。
6. **给选择带权衡**：需要用户选择时，给出几个选项及各自优缺点，并与核心理念挂钩，如 token 成本或对某功能的友好程度。
7. **站在使用者角度逐句检查**：假设读者已经打开当前文件，再逐句、逐段判断：去掉这段内容，是否会改变读者当前的判断、动作、输入、输出或避错结果？会改变才保留；不会改变就删除，或下沉到实际触发它的文件。不得把“文件是否需要读取”和“文件内某段内容是否有用”混为一谈。入口文件尤其只保留会影响下一步行动的内容，不写目录设计、维护意图或读者无需执行的说明。
8. **适配自留地**：`协作入口\Agent适配\` 按 Agent 划分，各 Agent 的适配文件只由对应 Agent 自己维护；优化其他线时发现适配问题，只记录不越界修改，交由对应 Agent 处理。

## Skill 索引

用户表达优化意愿后，**先问用户本次用什么方式**：用哪个已登记 skill，或不用 skill 由用户自行描述。这一问**只问方式**：禁止在同一问中夹带或追问目标、范围、细节等任何其他问题；目标与范围等用户选定方式后，在对应流程内确认。AI 不得自行读取某个 skill 直接执行；用户选定后才读取对应 skill 进入流程。已登记的可执行 skill：

| Skill | 用途 | 位置 |
|---|---|---|
| 优化流程线 | 按用户输入选一条线（线名不预设），按方针排查并优化 | 通用源码：[SKILL.md](../../工具/skills/体系优化/优化流程线/SKILL.md)；各平台加载方式见 [skills接入](../Agent适配/README.md) |

## 维护工具

| 工具 | 用途 | 使用方式 |
|---|---|---|
| 检查引用.ps1 | 扫描引用关系、高引用目标、孤儿、绝对路径残留、断链 | `powershell -File 检查引用.ps1`（全库）或 `-Target 成长`（指定范围）；优化某条线前先运行 |

PowerShell 工具脚本统一以 UTF-8 带 BOM 保存；无 BOM 时 Windows PowerShell 5.1 按 ANSI 解析中文，会乱码或报解析错误。
