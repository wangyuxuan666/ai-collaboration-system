# UX 设计方向须在可见形态上确认

## 结论

UX 的设计方向/关键取舍必须在可看的形态（线框稿/示意图，HTML/SVG，浏览器可打开）上经用户确认，模拟走查（人设走查）不能替代；用户核心诉求（如"一眼看复杂""树形结构"）须转成可测设计约束写入契约；设计契约须含"关键取舍与代价"节（每个取舍写明选了什么、代价是什么、是否已确认）。落点三处：`角色/模板/软件研发/开发/UX/设计契约模板.md`（新增"关键取舍与代价"节 + "完成证据"补可见形态确认）、`角色/角色列表/软件研发/开发/UX/UX.md`（成功指标 4）、`角色/角色列表/项目治理/总控/流程/代码开发流程.md`（第 4 节 UX 环节）。

## 为什么

1. 可视化工作台项目中，用户对设计方向（霓虹深蓝、首屏目录级）的确认基于文字描述而非可见形态，导致"盲拍板"：观感与结构不符预期、首屏"只看 7 个大文件夹"被用户认为糊弄。
2. DSH 平台能力确认：AI 窗口可产出线框/示意图（HTML/SVG，浏览器可打开）作为可见形态；成品设计图属图片设计师范畴，真实观感由前端渲染后用户确认。
3. 分工不变：方向在线框上确认（UX），观感在真实页面上确认（前端 UI 交付）。
