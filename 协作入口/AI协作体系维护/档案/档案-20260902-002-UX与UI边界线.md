# UX 与 UI 边界线落地

## 结论

划清 产品经理 / UX / 前端开发（UI 方向）边界：
- **产品经理**：概念 → 页面清单 + 每页核心（用途/要求/重点细节/边界）；
- **UX**：每个页面细化、整个逻辑搭建（信息架构、交互模型、页面结构、状态设计）；产出形态 = **"怎么用"的低保真逻辑轮廓/原型（最省 token，HTML/SVG 可打开）**，**不承担视觉样式**；
- **前端开发（UI 方向）**：**视觉样式与最终版效果（色板、组件外观、质感、动效），视觉方向由 UI 定**；按 UX 低保真原型+需求实现真实页面；
- **两个确认关口**：怎么用 = 看 UX 轮廓原型确认；长什么样 = 看 UI 真实页面确认。

## 为什么

1. 可视化工作台项目中 UX 越界做精致视觉线框稿（v2~v10 迭代、大量 token），视觉问题到 UI 交付才暴露（廉价感）；职责划分方向本对，缺的是边界表述不具体。
2. 用户判定：UX 决定"怎么用"（最省 token 的轮廓），UI 决定"长什么样"（样式与最终版）；每个环节保留，按此划清边界。
