# 档案：Agent 适配工具接入机制 SOP 化

## 结论

工具接入机制重构为"入口 + SOP + 参数"三层：各平台通用故障排查 SOP 上收到 `Agent适配/README.md`（唯一权威一份）；三平台入口规则只保留"接入硬性检查点"（触发后指向 SOP）；各平台 `MCP接入.md` / `skills接入.md` 只保留平台特有参数，删除各自重复的"处理规则"段。同时 browser-skill 从通用 `工具/skills/` 下分到 DSH 专属 `Agent适配/DSH/skills/`，写死路径改为"占位符 + AI 现场检测"式写法。

## 为什么

1. 三个平台的"处理规则"4 条逐字重复，违反"唯一权威"；流程应只定义一处。
2. 用户目标：新用户拿到体系但未装任何环境时，AI 触发工具失败能按统一 SOP 排查（没装 vs 没链接）、引导安装并验证，而非各平台各写一套。
3. SOP 内容短（约 230 字），放入总入口（每窗口必读）可保证"永远在场"，不建独立文件。
4. browser-skill 本质是 DSH 平台能力（bsk CLI），登记表平台列本就是 DSH，放通用目录属归属错位；按"共用上收、平台差异下分"下分到 DSH。
5. 写死的机器路径（`D:\ai\dsh-data`、`C:\Users\admin` 等）对本地 AI 和新用户都无执行价值（环境会变），改为占位符 `<程序目录>` + 检测方法（`Get-Command bsk`、`$env:USERPROFILE`），环境无关。

## 影响范围

- 新建 `协作入口/Agent适配/README.md` SOP 段（工具接入与故障处理 SOP，各平台通用）
- `协作入口/Agent适配/{Codex,DSH,Hermes}/入口规则.md`：接入硬性检查点改为指向总入口 SOP
- `协作入口/Agent适配/{Codex,DSH,Hermes}/MCP接入.md`、`skills接入.md`：删除"处理规则"段，加 SOP 指引行，保留平台参数
- `Codex/MCP接入.md`：`C:\Users\admin\.codex\config.toml` → `<用户目录>\.codex\config.toml`
- 迁移 `工具/skills/browser-skill/README.md` → `协作入口/Agent适配/DSH/skills/browser-skill/README.md`（路径 C 式写法）
- `工具/skills/README.md`：删 browser-skill 登记行与触发表行
- `DSH/skills接入.md`：已登记表新增 browser-skill（DSH 专属）
- 新窗口流程模拟测试后修复 3 处措辞歧义（"本索引"→"本入口"、插件能力表头、浏览器操作行断链提示）
