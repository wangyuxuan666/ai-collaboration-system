# 需求文档模板

## 使用说明

- **产出标准**：需求文档把产品经理负责的部分写清——背景与目标、范围、页面清单（业务职责级）、每页概要、流程、验收、假设与待决问题；不写设计/技术细节（配色、控件样式、接口、建表）。体验结构（信息架构、交互模型）由 UX 承接，不在本文档展开。
- **三档裁剪**（按影响范围判断，不按文档长度）：
  - **简版**：改文案、按钮、单字段，不动流程 → 只写：范围 + 改动点 + 验收。
  - **标准版**：新增页面/功能，涉及交互和流程 → 八大节全写，每节从简。
  - **全版**：新产品、大改版、跨模块流程 → 八大节完整 + 每页概要 + 流程详述。
- 分档判断：新增页面 ≥2 或涉及流程变化 → 标准版；涉及多模块/角色或全新产品 → 全版；其余 → 简版。
- 相关知识按需读取：拆页面看[页面清单与每页概要要素](../../../../知识库/Wiki/产品/需求文档/知识/页面清单与每页概要要素.md)；需求不清晰看[需求模糊冲突遗漏识别](../../../../知识库/Wiki/产品/需求分析/知识/需求模糊冲突遗漏识别.md)；标优先级看[需求优先级标注方法](../../../../知识库/Wiki/产品/优先级/知识/需求优先级标注方法.md)。

# 一、概述

- 项目状态（筹备中 / 进行中 / 已归档）、文档状态（草案 / 待评审 / 已确认）、参与者（产品/设计/研发负责人）、目标发布。
- 产品形态与载体：小程序 / Web / App / 桌面端（影响页面清单与导航形态）。

# 二、背景与目标

- 为什么做：解决什么问题、用户痛点或业务原因。
- 目标：做成什么样算好（2-3 条，可感知、可衡量）。
- 非目标：明确不解决什么。

# 三、范围

- **做什么**：本次包含的功能点清单（每项标功能级优先级 P0/P1/P2：P0=核心必须做、P1=应该做、P2=可以做）。

| 功能点 | 优先级 | 说明 |
| --- | --- | --- |
| 例：发布二手书 | P0 | 核心闭环 |
| ... | ... | ... |

- **不做什么**：明确写出的范围外事项（防需求膨胀的关键）。

# 四、页面清单

- 列出全部页面与关键弹窗，每页一句话职责 + 页级优先级（P0=必须交付、P1=应该交付、P2=可以延后）；功能点级优先级已在范围节标过，页面清单不重复标功能点。

| 页面 | 职责 | 页级优先级（P0/P1/P2） |
| --- | --- | --- |
| 首页 | 一句话 | P0 |
| ... | ... | ... |

# 五、每页概要

对每个页面写四要素：

- **用途**：这页解决什么问题、用户来这页干什么。
- **要求**：这页必须满足的核心条件。
- **重点细节**：有（具体元素/功能点）；没有（明确不做的）。
- **边界**：什么不在这页做、与其他页的分界。

# 六、流程

- 主流程：页面怎么串、用户怎么走完这件事（步骤式或表格）。
- 分支/异常：关键分支与失败路径（简要）。

# 七、验收

- 怎么算做完：可测的标准（建议 Given-When-Then：给定背景，当发生什么，则结果如何）。
- 按优先级核对：P0 必须全部通过；P1/P2 按约定。
- 验收标准必须覆盖用户的核心诉求（含体验/结构类原话要求，如"一眼看复杂""树形结构"），每条核心诉求至少对应一条可测验收项。

# 八、假设与待决问题

- 假设：技术/业务/用户行为假设，标注待验证项。
- 待决问题：需要用户或团队决定的事项清单。

# 九、文档变更记录

需求文档确认后，任何修改必须先经用户确认；确认后由发现或提出修改的窗口直接修改，并在下表逐条追加留痕（日期＋修改人＋改了啥＋依据）；未获用户确认不得修改。不需要经产品经理窗口中转。

| 日期 | 修改人（窗口） | 改了啥 | 依据 |
| --- | --- | --- | --- |
| （示例）2026-09-05 | UX | 案例表第 6 条后加省略行 | 用户确认 |

# 填充示例（二手书交易小程序 · 标准版）

> 以下为示范写法，展示粒度；实际按任务裁剪。

## 一、概述
- 状态：待评审；参与者：产品（本角色）、研发负责人（待指定）；目标发布：待定。

## 二、背景与目标
- 为什么做：用户有闲置二手书无处处理、想买低价书没有可靠渠道；现有平台流程复杂、运费规则不透明。
- 目标：用户从发布到售出 ≤3 步；买家能找到目标书籍；买卖双方能完成线下或邮寄交易。
- 非目标：不做自营书库、不做电子书。

## 三、范围
- 做（功能点清单）：发布书籍（P0）、浏览/搜索（P0）、下单-沟通式（P0）、订单管理（P1）、个人中心（P1）。
- 不做：自建支付、物流跟踪、评价系统、平台客服工单。

## 四、页面清单

| 页面 | 职责 | 页级优先级 |
| --- | --- | --- |
| 首页 | 浏览推荐书、搜索入口、分类入口 | P0 |
| 详情页 | 展示一本书的完整信息与卖家信息、发起沟通 | P0 |
| 发布页 | 填写书籍信息并上架 | P0 |
| 订单页 | 我的订单列表与状态 | P1 |
| 我的 | 个人资料、我的发布、我的收藏、设置 | P1 |
| 搜索结果页 | 独立的结果列表页（从首页搜索进入） | P1 |

## 五、每页概要（示例：首页）

- 用途：让用户快速找到想买的书，是第一入口。
- 要求：打开即可看到推荐书与搜索入口；加载失败可重试。
- 重点细节：首页承担"找书"主入口职责：搜索与分类找书、推荐在售书。具体要不要做登录弹窗、广告位、个性化推荐，属体验层取舍，由 UX 在体验设计中给出建议；元素级布局（搜索栏放哪、底部导航几个）由 UX 在体验页面结构中设计，不在此展开。
- 边界：不承担发布功能（发布入口在"我的"与底部导航）；搜索结果页独立，不在首页内嵌。

（其余页面按同格式填写，简写即可。）

## 六、流程

- 买家：首页浏览/搜索 → 详情页 →（沟通议价）→ 订单页确认 → 完成。
- 卖家：我的 → 发布页上架 → 收到买家沟通 → 确认交易 → 订单页完结。
- 分支：买家取消 → 订单状态变"已取消"；卖家下架 → 详情页显示"已下架"。

## 七、验收（示例 2 条）

- Given 首页有 ≥3 本在售书，When 用户打开首页，Then 显示推荐书列表且每本含封面/书名/价格，搜索栏可用。
- Given 书籍已下架，When 用户打开其详情页，Then 显示"已下架"且不显示"联系卖家"入口。

## 八、假设与待决问题

- 假设：交易为买卖双方私下沟通完成，平台仅撮合（待用户确认）。
- 待决：是否支持同城优先排序？运费由谁承担展示？
