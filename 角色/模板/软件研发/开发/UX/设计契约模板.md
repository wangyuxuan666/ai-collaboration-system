# [页面] 设计契约

本模板由 UX 在形成页面或关键流程的设计契约时填写，作为前端 UI 实现的依据；每个页面或关键流程一份。经用户确认后生效，确认前不进入 UI 实现。

## 用户与任务

[谁在什么场景下要完成什么；写具体，不写"用户要浏览页面"]

## 首读对象

[进页面第一眼必须看到的东西；看不到它就算页面失败]

## 主操作

[要引导用户完成的一个主要动作；多于一个时按优先级列出]

## 信息层级

[标题 / 关键信号 / 控件 / 次要信息的排列；层级由用户决策驱动，不沿用组件默认]

## 交互模型

[表格 / 画布 / 编辑器 / 时间线 / 表单 / 列表……选一个主模型并说明为什么]

[窄屏时什么保留、什么折叠、什么移动；不是简单堆叠卡片]

## 禁用默认项

[本产品禁止的"千篇一律"默认样式：如四张等权指标卡、装饰渐变、无层级卡片、通用空态；写明具体禁止什么]

## 关键取舍与代价

[本设计做过的取舍，每个取舍写明：选了什么、代价是什么（失去什么）、是否已请用户确认。例：首屏只展开到目录级 → 代价是第一眼看不到丰富度，用户已确认]

## 完成证据

[验证了什么、在哪些视口和状态下验证的；以证据为准，不写"我觉得好"]

设计方向/关键取舍必须在**低保真逻辑轮廓/原型**（线框/示意图，HTML/SVG，浏览器可打开）上经用户确认，并在本文件记录确认结论；模拟走查（人设走查）不能替代用户对设计方向的确认。视觉样式（色板、组件外观、质感、动效）不在 UX 稿中承担，由前端 UI 方向实现。
