## 2. 数据模型

先定义数据长什么样，接口字段才有依据。

### 2.1 实体与字段

| 实体 | 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|---|
| 示例：留言 | id | BIGINT | 主键，自增 | |
| | nickname | VARCHAR(50) | 必填 | 对应页面"昵称"输入框 |
| | email | VARCHAR(100) | 必填，邮箱格式 | |
| | content | TEXT | 必填，最大 1000 字 | |
| | status | ENUM('待处理','已处理') | 默认待处理 | 对应后台"标已处理" |
| | created_at | DATETIME | 自动记录 | |

- 示例：用户 1—N 订单（一个用户多个订单）；订单 N—N 商品（通过订单项关联）。

- 表命名、索引、唯一约束、软删除等按项目技术栈与规范执行；此处只登记与接口直接相关的约定。

## 3. 接口清单

由技术经理从已敲定页面和功能点推导边界与调用方/提供方；由后端负责人细化字段与错误处理。

### 3.1 鉴权与访问约束

- 哪些接口需要登录/权限，用什么方式（Token / Cookie / 其他），公开接口与受保护接口的分界。

### 3.2 接口表（按模块分组，所属模块与技术经理拆定的功能模块一致）

| 所属模块 | 接口或事件 | 方法 | 调用方 | 提供方 | 用途 | 请求或触发条件 | 返回、结果或状态变化 | 错误与异常处理 |
|---|---|---|---|---|---|---|---|---|
| 模块 1：留言管理 | /api/messages | POST | 前端（留言页） | 后端 | 提交留言 | body: {nickname, email, content} | 201，返回 {id, created_at} | 400 参数校验失败；500 服务器错误 |
| | /api/messages | GET | 前端（后台管理页） | 后端 | 留言列表 | query: page, size, status | 200，返回列表与总数 | 401 未认证；403 无权限 |
| | /api/messages/{id} | PATCH | 前端（后台管理页） | 后端 | 更新留言状态 | body: {status} | 200，返回更新后留言 | 404 不存在；409 冲突 |
| 公共 | /api/login | POST | 前端（登录页） | 后端 | 登录获取凭证 | body: {username, password} | 200，返回 token | 401 凭证错误 |

**所属模块填写规则**：模块名以项目协作目录"代码开发模块进度"的模块名为准（唯一来源）；登录、鉴权等跨模块公共接口填"公共"，不归任何业务模块。

**错误与异常处理列填写要求**：按接口的错误大类使用标准 HTTP 状态码（400 参数校验失败、401 未认证、403 无权限、404 不存在、409 冲突、500 服务器错误），响应体返回统一的 JSON 错误结构（错误码、提示信息、详情），并区分系统级（状态码）与业务级（业务错误码）错误；生产环境不向客户端暴露底层异常堆栈。完整规范以知识库接口错误处理为准，本列只登记该接口的实际约定。

- 时间格式、枚举值、分页约定、空值处理、版本兼容规则。
