# 优化角色流程

## 1. 流程定位

本流程用于优化一个已经存在并正在实际使用的角色。目标是根据真实使用中暴露的不足改善角色定位和实际表现，不是把每次问题都改写成永久规则。

本流程每次只优化一个角色。用户确认优化方案前不写入文件。

开始优化前读取 [角色设计理念](../参考资料/角色设计理念.md)，将其作为根因判断和角色设计依据，不作为固定检查顺序。

## 2. 理解实际问题

角色管理员先理解当时的任务和场景、角色的实际表现、用户认为不足的原因、期望的思考或行为，以及必须保留的原有能力。

用户提出的修改办法是重要输入，但不能代替角色管理员对根因和影响范围的独立判断。能够根据现有信息判断时自行判断；确实缺少会影响优化方向的信息时，一次只询问一个问题。

只读取当前角色核心文件和与问题直接相关的专业领域、流程、参考资料、模板、规则或入口。只有问题涉及询问行为时才读取免询问文档，不为排查而全量加载角色资产。

## 3. 判断问题归属

```text
发现角色表现不足
├─ 单次执行偏差
│  └─ 不一定修改长期文件
├─ 基础角色定位不准确
│  └─ 检查角色核心文件
├─ 缺少相关领域知识
│  └─ 检查对应专业领域文件
├─ 任务推进方法不合适
│  └─ 检查任务流程
├─ 缺少稳定参考依据
│  └─ 检查角色参考资料及其登记入口
├─ 规则造成错误限制
│  └─ 检查角色规则或通用规则
├─ 启动、角色或专业领域选择错误
│  └─ 检查入口和索引
├─ 任务文档不能准确传递目标
│  └─ 检查相关模板
└─ 工具、权限或运行环境问题
   └─ 不误判为角色设计缺陷
```

角色核心文件主要负责“角色是谁”；专业领域文件主要负责“角色进入该领域后需要知道什么”；流程主要负责“某类任务可以怎样推进”；参考资料提供特定任务需要查阅的依据；规范只保存确实需要强制遵守的要求。

不得因为一次失败就增加大量禁止事项、固定步骤或机械判断条件。问题属于单次执行偏差或外部环境时，应如实说明，不为产生文件修改而强行修改角色。

## 4. 形成优化方案

角色管理员根据根因判断需要修改哪个文件、是否需要修改角色本身、是否只需补充专业领域知识或参考资料，以及修改是否会削弱自主判断或影响其他角色。

写入前向用户提交精简方案，至少说明：

- 当前问题与根因判断；
- 拟修改文件及各自的修改理由；
- 预期改变的角色表现；
- 必须保持不变的能力；
- 同步影响、主要风险和验证方式。

存在多个会实质影响结果的方案时，说明差异和推荐，只把必要选择交给用户。用户明确批准具体优化方案，即构成执行授权，不再重复询问是否开始优化。

## 5. 执行优化

用户批准方案后，只修改方案中已经确认的文件：

- 优先纠正角色定位和专业理解；
- 能通过正确定位解决时，不增加行为脚本；
- 能修改专业领域时，不把领域内容写进角色核心文件；
- 能修改流程时，不把操作步骤写成角色身份；
- 参考资料只登记准确路径和适用场景，不把资料正文复制进角色核心文件；
- 能引用现有规则和知识入口时，不复制正文；
- 不顺带修改无关角色或文件。

执行中发现实际结构会实质改变已确认方案时，暂停并向用户说明；能够在不改变目标和影响范围的前提下合理适配时，自行处理实现细节。

## 6. 验证优化结果

优化完成后至少检查（体系级语义检查按[语义检查清单](../../../../../协作入口/规范/语义检查清单.md)逐项执行）：

- 使用最初暴露问题的场景重新验证；
- 角色是否更接近用户期望的定位和表现；
- 原有正确能力是否保留；
- 通用状态是否仍能正常工作；
- "知识库读取"节是否统一为按任务从知识索引检索、不预置固定读取清单；
- "身份定位"是否保持身份式写法（写"是谁"不写"怎么做"），与"价值观"无重复，立场类内容是否已归位到价值观；
- "价值观"是否与角色实际立场匹配，是否仍是具体短语而非空话口号；
- "数据边界"是否与实际负责和访问的资产一致，引用路径有效，且没有与专业领域、参考资料等节重复正文；
- 涉及专业领域时，加载前后的专业定位是否准确；
- 涉及参考资料时，是否只在相关任务中按需读取且引用路径有效；
- “流程”“专业领域”“参考资料”“资产目录”四个固定目录是否完整，空目录中是否没有占位文件；
- 是否新增不必要的询问、规则或固定步骤；
- 入口、索引、文件路径和登记名称是否一致。

验证不能只检查文件是否存在，还要模拟角色启动后的理解、判断和行动。场景验证关注目标是否达到、关键判断是否合理、边界是否守住和结果能否验证，不以是否逐字遵循同一过程作为合格标准。

## 7. 结果反馈

向用户说明实际修改内容、预期行为变化、验证结果，以及仍未解决的问题或风险。
