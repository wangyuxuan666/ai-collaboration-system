# Gitee 仓库创建与目录登记

## 0. 开工前：按知识库入口检索

开始处理前，按身份定位·价值观核对本次安排：结构清晰、资产可追溯、访问边界、凭据安全、不越界；任务涉及可复用专业结论时，按[知识库入口](../../../../../知识库/入口.md)检索相关规范或知识，命中且影响本次处理时读取，未命中则跳过检索，不阻塞后续工作。

## 1. 适用场景

新建项目、为现有项目新增 Git 远程地址、接手已有仓库，或需要整理项目类别、项目组和组件仓库关系。

## 2. 目标

使项目组中的每个前端、后端或其他可独立维护组件都具有独立、可定位的 Gitee 仓库，并能从项目目录追溯其类别、职责和关联仓库。

## 3. 处理参考

- 接收总控已确认的建库任务时，先查看资产目录并按需核对 Gitee 当前状态，识别项目应使用的已有组织或待创建组织。
- 已有组织可承载项目时，在该组织下创建符合命名规则的独立组件仓库；组织不存在且任务已明确授权时，先创建组织再创建仓库。
- 组织路径冲突、项目归属不清或用户确认内容缺失时，向总控回报需要确认的事项，不擅自选择替代组织或路径。
- 建库、改名、转移或调整可见性后，更新 `资产目录\Gitee资产目录.md`；新仓库同时登记职责、远程地址和已确认的首次拉取目录。
- 按任务需要首次拉取并交接；不需要首次拉取的仓库，应在资产目录中明确记录“无需首次拉取”。

## 4. 治理原则

- 项目类别用于归档和筛选，项目组用于聚合一个业务项目，仓库是可独立维护的组件；三者不得混淆。
- 仓库命名遵守 [Git 管理员](<../Git 管理员.md>) 中定义的结构；无法适用时说明原因并取得用户确认。
- 任何新增 Git 远程地址均由 Git 管理员创建或完成接入登记。其他角色不得自行创建、接入或遗漏登记。
- 仓库与归属、职责、地址、状态一律登记在全局[Gitee资产目录](../资产目录/Gitee资产目录.md)，项目内不另建项目仓库目录；仓库 README 按需链接关联仓库。
- 完成首次本地拉取并交接后，本角色不再介入该仓库的日常 Git 或版本协作操作。

## 5. 完成检查

- 项目类别、项目组、组件职责和仓库命名可以相互定位。
- 远程地址、本地首次拉取目录和资产目录记录一致。
- 仓库可见性、成员权限和归档状态符合已确认的要求。
- 项目存在多个组件仓库时，各仓库 README 能说明关联关系。
