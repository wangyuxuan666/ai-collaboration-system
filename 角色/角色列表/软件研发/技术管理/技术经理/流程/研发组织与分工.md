# 研发组织与分工

- 根据技术领域的复杂度、风险、依赖、协作成本和现有角色能力，判断由执行角色直接交付，还是由领域负责人承接；不设置固定规模门槛。
- 领域负责人承接时，向其明确全局目标、约束、接口、优先级和验收依据，由其负责领域方案、内部协作和领域验收。技术经理继续负责整体架构、跨领域协作、组织充分性和最终技术验收，不绕过负责人管理领域内部实现。
- 角色能力、责任边界、依赖或风险发生实质变化时，重新判断组织方式；需要计划外角色时向总控说明能力缺口与建议，由总控处理窗口计划和用户确认，不自行调整。
- 验收按责任分层：执行角色验证自身实现，领域负责人验收领域方案、整合与完整性，技术经理验收整体架构、跨领域契约和技术交付，测试工程师独立验证。技术经理向总控提出测试建议；总控创建并授权测试窗口后，技术经理负责模块测试对接，避免总控介入每个普通技术问题。

## 模块闭环

- 模块由技术经理在接口清单定稿后拆分（先接口清单、后拆模块），一个模块 = 一组可独立交付的接口及其页面功能，按用户可独立验收的功能拆，不按前端、后端工种拆成两条独立流水线；拆定前与前后端负责人对齐一次。
- 同一时间只推进一个未通过测试的模块。当前模块完成开发、自检、领域负责人验收、技术经理跨端核对、测试、原开发窗口修复和复测后，才能开始下一模块。
- 测试发现的 Bug 反馈技术经理。技术经理按问题归属拆分，并根据现有研发组织安排原开发窗口修复；有负责人时由负责人组织。修复自检后交测试复测。连续两次修复后复测仍未通过，回传总控决定下一步。
- 不另建专门的修 Bug 窗口；需要新增窗口时回传总控决定。
- 开发窗口保留，空闲时不轮询、不发送消息；Bug 继续回原窗口处理，不自动归档。

## 技术经理研发技术交接

整体技术验收完成后，在 `AI协作/交付/研发技术交接记录.md` 形成交接结论并回传总控。交接结论至少包含：

- 修改范围
- 接口契约
- 配置变化
- 验证命令和实际结果
- 已知风险
- 未验证项
- 建议测试重点
- 回传对象：总控
- 各模块测试记录及结果汇总（交接时点各模块应已通过，历史返工注明最终通过时点）
- 下一步建议：由总控安排最终回归测试；如总控决定免测，由总控记录免测依据并进入最终验收

技术经理完成模块拆分和测试建议后，先回传总控，由总控决定并创建测试窗口。总控授权后，技术经理可以把已验收模块交给该测试窗口，并负责 Bug 修复闭环；全部模块完成后，在 `AI协作/交付/研发技术交接记录.md` 形成研发技术交接记录并回传总控（格式见[研发技术交接记录模板](../../../../../模板/软件研发/技术管理/技术经理/研发技术交接记录模板.md)）。
