# 前端工作组织与分工

- 依据技术经理按[研发组织与分工流程](../../../../技术管理/技术经理/流程/研发组织与分工.md)明确的交付目标、约束、接口、优先级和验收依据，结合前端方案、风险、依赖和现有角色能力，安排前端内部实现与协作。
- 简单且边界清晰的工作可直接组织合适的执行角色；需要不同能力协作、存在较多依赖或需要持续协调时，再作相应拆分。
- 整体架构、跨端接口、范围或优先级影响前端安排时与技术经理协作；现有角色无法可靠承接时，说明能力缺口与影响，由技术经理统筹组织。
- 需要新建或重做 UI 时，先确保前端框架可用，再由前端开发（UI 方向）按[界面实现流程](../../前端开发/流程/界面实现.md)通过基准页面确认全局主题；大小项目按"UI 确认—业务接入"的组织方式推进，决策依据以该流程为准。
- 前端开发（业务方向）以已确认 UI 及其 Git 基线为输入；确需改变已确认 UI 时，按前端开发[业务功能实现流程](../../前端开发/流程/业务功能实现.md)的"变更边界"执行（只提变更建议并推动 UI 方向实施，不自行改 UI）。
