# 界面实现

用于在已搭建的前端框架内，通过可运行页面逐步确认设计方向并完成前端 UI 系统。

## 0. 开工前：按知识库入口检索

开始实现前，先按[知识库入口](../../../../../../../知识库/入口.md)检索"代码开发/前端工程"分组的规范知识，读取命中且影响本次实现的页面，按其规范实现；未命中则跳过，不阻塞任务。结合[UI 方向专业领域](../专业领域/UI.md)核对以下实现方面：

- [ ] 组件拆分与复用
- [ ] 样式与选择器组织
- [ ] 状态与数据接入
- [ ] 响应式与可访问性
- [ ] 构建与性能
- [ ] UI 方向补充：设计系统一致性、界面状态覆盖、交付形态

## 1. 理解设计问题

理解产品目标、使用者、页面内容、关键操作、现有品牌或界面资产和技术约束。信息不足时，优先通过少量有区分度的问题、现有网站和实际内容理解用户偏好；结合专业判断提出推荐，不把空白画布交给用户设计。

## 2. 风格方向确认

新建或重做 UI 时**一律先做风格方向确认**，除非用户明确表示沿用既有视觉体系：在建立界面基线前，先用 UIUXProMax 出 2-3 套差异化风格候选（风格+配色+字体+效果+反模式；用不同关键词或 `--variance`/`--motion`/`--density` 旋钮拉开差异；skill：用时 read `工具\skills\UIUXProMax\SKILL.md` 后按步骤执行），交付用户挑选。用户明确选定一套后，作为设计约束进入"建立界面基线"；**用户未选定方向前不得实现基准页**。skill 输出只作参考，最终方向由用户拍板。

## 3. 建立界面基线

确认前端框架已经搭建并适合承载界面后，先建立设计 token（颜色、字体、间距、阴影）与基础组件，再选择最能代表整体产品的基准页面，通常为首页。首页不能代表核心产品时，说明理由并选择更合适页面。使用真实结构、代表性内容或模拟数据直接实现可运行页面，不以图片代替交互系统。

基准页面应呈现足以判断方向的布局、层级、字体、颜色、组件、响应式行为和关键交互状态。**必须先交付这一个基准页面给用户确认风格**；**用户未明确确认主题与界面基线前，不得实现或交付其余页面**（硬性门槛，违反即本节点不通过）；确认后才可铺开其余页面，并根据用户反馈快速修改。

## 4. 扩展页面系统

基线确认后，复用已确认的设计变量、公共组件和交互模式实现其余页面。每页按真实业务场景补足相关的加载、空数据、失败、弹窗、反馈和边界状态，使后续业务方向可以替换模拟数据、接入状态和接口，而不必重做页面结构。

所有项目一律先按第 3 节完成基准页与界面基线确认，再铺开其余页面，不设"小项目可先全做完"的例外。大型项目可以在全局主题确认后按模块推进，每个模块先确认 UI，再由业务方向接入该模块；采用哪种组织方式由项目规划根据规模、依赖和返工风险决定。

## 5. 自测与交接

按第 0 步的核对项逐项自测：以实际运行效果检查目标视口、关键交互、状态覆盖、组件一致性、兼容性和可访问性。交付已确认页面、设计基线和组件入口，列明模拟数据边界、尚未实现的业务逻辑和已知问题。已确认的 UI 应形成可定位的 Git 基线，具体提交由项目的 Git 协作安排执行。
