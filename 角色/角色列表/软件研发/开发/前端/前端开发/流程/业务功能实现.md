# 业务功能实现

用于在已确认的前端框架、UI 系统和接口契约内实现页面业务功能。

## 0. 开工前：按知识库入口检索

开始实现前，先按[知识库入口](../../../../../../../知识库/入口.md)检索"代码开发/前端工程"分组的规范知识，读取命中且影响本次实现的页面，按其规范实现；未命中则跳过，不阻塞任务。通用核对项（组件拆分与复用、样式与选择器组织、状态与数据接入、响应式与可访问性、构建与性能）见[代码开发验证核对表](../../../../../../模板/项目治理/代码开发验证核对表模板.md)，不在此重复；结合[业务方向专业领域](../专业领域/业务.md)核对方向补充项：业务状态管理、复用与接入、变更边界。

## 1. 理解实现要求

核对当前角色窗口任务包、已确认 UI 及其 Git 基线、接口契约和验收标准的一致性；识别需求、UI、接口或既有能力中的缺失、冲突和实现风险，说明影响并提出建议。信息不足以可靠实现时，先补足或澄清，不带矛盾开始实现。

## 2. 实现业务功能

在已确认的可运行 UI 系统上实现页面业务、状态管理、数据接入和联调，按第 0 步检索到的规范执行：优先复用既有页面结构、组件和交互状态；确需改变已确认 UI 时，先说明影响并推动重新确认，不把实现便利当作修改设计的充分理由。

## 3. 自测与交接

按第 0 步的核对项逐项自测：实际运行检查关键状态、交互、响应式与可访问性，并核对接口接入与错误处理；发现不符合规范处先修正再继续。完成后在当前角色窗口任务文件和交付物中记录必要信息，使用平台实际窗口 ID 与已确认的协作对象衔接，进入验收。

## 4. 后续缺陷修复

被测试或负责人回派修复 Bug 时，仍在原开发窗口承接，按[研发组织与分工](../../../../技术管理/技术经理/流程/研发组织与分工.md#模块闭环)修复并交复测，不另建修 Bug 窗口；窗口在项目验收前保留，空闲时不轮询、不发送消息。
