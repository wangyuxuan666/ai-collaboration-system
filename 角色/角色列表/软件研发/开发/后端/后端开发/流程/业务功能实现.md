# 业务功能实现

用于在已确认的后端方案、数据模型和接口契约内实现业务功能。

## 0. 开工前：按知识库入口检索

开始实现前，先按[知识库入口](../../../../../../../知识库/入口.md)检索"代码开发/后端工程、数据访问、数据一致性、API"分组的规范知识，读取命中且影响本次实现的页面，按其规范实现；未命中则跳过，不阻塞任务。通用核对项（接口与契约、数据访问安全、数据一致性、错误与日志、性能与效率）见[代码开发验证核对表](../../../../../../模板/项目治理/代码开发验证核对表模板.md)，不在此重复；结合[业务方向专业领域](../专业领域/业务.md)核对方向补充项：业务规则与数据、验证与联调、变更边界。

## 1. 理解实现要求

核对当前角色窗口任务包、已确认后端方案、数据模型、接口契约和验收标准的一致性；识别实现所依赖约束中的缺失、冲突和风险，说明影响并提出建议。信息不足以可靠实现时，先补足或澄清，不带矛盾开始实现。

## 2. 实现业务功能

在已确认的后端工程基础上实现业务规则、数据处理和服务接口，按第 0 步检索到的规范执行：优先复用既有公共模块、中间件和接口模式；确需改变已确认方案、数据模型或接口契约时，先说明影响并推动重新确认，不把实现便利当作修改设计的充分理由。

## 3. 自测与交接

按第 0 步的核对项逐项自测：核对接口契约、数据访问、事务边界、错误处理与性能符合约定；发现不符合规范处先修正再继续。完成后向协作方提供可用于联调和独立验证的实现结果及必要的交付信息，进入验收。

## 4. 后续缺陷修复

被测试或负责人回派修复 Bug 时，仍在原开发窗口承接，按[研发组织与分工](../../../../技术管理/技术经理/流程/研发组织与分工.md#模块闭环)修复并交复测，不另建修 Bug 窗口；窗口在项目验收前保留，空闲时不轮询、不发送消息。
