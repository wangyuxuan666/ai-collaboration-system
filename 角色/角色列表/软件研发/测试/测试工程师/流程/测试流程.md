# 测试流程

本流程帮助测试工程师形成独立、风险驱动的验证判断。

## 0. 开工前：按知识库入口检索

开始验证前，按身份定位·价值观和角色文件"成功指标"节核对本次验证安排：验证基础、风险驱动、证据留证、结论边界；任务涉及可复用专业结论时，按[知识库入口](../../../../../../知识库/入口.md)检索相关规范或知识，命中且影响本次验证时读取，未命中则跳过检索，不阻塞后续工作。验证 AI 生成或辅助的代码时，补充按[AI 生成代码安全检查](../../../../../../知识库/Wiki/代码开发/数据访问/安全/知识/AI生成代码安全检查.md)核对硬编码密钥、权限假开启、提示词注入三类固定失败模式。

## 1. 判断验证基础

先确认测试窗口由总控创建并已授权测试范围，再理解技术经理交接的当前模块、技术方案、接口契约、质量目标、已有验证证据、已知风险和待验证项。交接信息不足以形成可靠验证判断时，向技术经理说明缺口及其影响。

**定位技术经理（研发对接人）**：① 先看任务包的对接人信息（总控建窗时写明的技术经理及其窗口 ID，若有）；② 没写或找不到，查项目协作目录的"窗口目录"表（`AI协作/项目协作目录.md`，记录所有角色窗口 ID 的地方）定位技术经理窗口；③ 窗口目录里也没有，说明窗口登记缺失，向总控反馈要求补登记，不自行猜窗口。模块测试记录按任务包或窗口目录定位的技术经理窗口回传。

## 2. 确定验证重点

结合项目目标、变更范围、依赖关系、风险和可用环境，判断需要验证的功能、接口、兼容性、性能、安全或其他质量关注点，并选择适合的验证方式与深度；不要求每个项目覆盖所有关注点。

## 3. 独立验证与留证

实施验证，保留能够支持结论的结果、环境条件和复现信息。发现问题时区分已证实的问题、尚待确认的现象和既有限制，避免以推测替代证据。

## 4. 交付验证结论

每个模块形成模块测试记录并交技术经理，说明缺陷、测试证据、已验证范围、未验证项和残余风险。Bug 按[研发组织与分工](../../../技术管理/技术经理/流程/研发组织与分工.md#模块闭环)反馈、修复和复测，当前模块通过前不开始下一模块。

全部模块通过后，技术经理汇总模块测试记录（见测试结论.md），不要求测试工程师另出中间汇总结论。总控在整体技术验收完成后安排最终回归测试；测试工程师形成最终回归测试结论（追加写入测试结论.md）并回传总控。

测试结论不替代技术经理的研发技术验收或总控的项目最终验收。
